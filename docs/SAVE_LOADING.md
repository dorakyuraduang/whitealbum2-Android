发现并修正的额外开销：

- 共享文件 API 的 CreateFile 先查询是否存在，再解析共享锁用的路径，最后打开文件。原目录别名适配器在这三步中反复解析同一文件，根目录已有文件会触发四次底层元数据查询。现在 `MutableFiles::OpenPlan` 在一次 API 操作内保留已解析的元数据、别名与打开动作；共享锁检查仍在创建或截断文件之前。下一次 API 操作重新查询，不保留跨操作的文件缓存。

- `GameDocuments` 的各入口清空索引并串行执行，包括启动页复用同一对象的情况。新操作立即看见外部替换或新增文件；没有依赖超时失效，也没有缓存 PAK 或存档内容。
- 快进策略原先只检查外层故事状态，存读档界面也处于该状态。现在显式排除缓存界面状态 6/7，防止遗留快进标记令文件界面进入加速换帧路径。必要的资源/线程等待不被省略。

## 0.2.54：首次列表的章节索引

用户继续反馈“继续游戏”首次列出存档仍慢。缓存 CFG 显示，首次初始化在 `0x41d507`、`0x41d67b` 调用的是 `0x4233c0`，读取 24 字节时间头部，并分别使用根目录前缀 `0xa39d28` 和另一存档目录前缀 `0xa39270`。此前回归主要调用 `0x4234c0` 的大预览读取路径，且共享清单分支只接受没有斜杠的根目录文件名；章节路径因此继续逐个查询。这是单文件打开提速没有覆盖的具体遗漏。

现在每个已知章节目录也在同一源更新/状态内建立独立索引。根清单没有 Documents 时直接判定其下章节不存在；目录存在时首次列举一次，包括空目录/空槽位。根目录的旧 PC 后备路径、introductory/closing 两个章节及测试前缀各自保留边界。任意本应用写入、下一更新、状态变化和 250 ms 到期仍刷新；有效文件的内容和描述符不缓存，不改变列表、时间数据或排序的源函数。

新增自建文件检查调用未修改的 `0x4233c0`，在两种内存模式下分别扫描两组 100 个槽位，覆盖章节存在/不存在、相同槽位不同数据、当前更新内修改、章节切换、写入、新更新和提供者拒绝目录枚举。合计 1614 次时间索引调用。示例中 298 次元数据查询变为最多 3 次目录枚举；Documents 不存在时仅 1 次。两边仍打开并读取相同的有效头部。原有 868 次预览读取检查保留。此结果是组件访问次数，不是用户手机的首次列表秒数。

用户两次确认退出后，取回的报告仍停留在 0.2.51，不能继续作为新版本的证据。新增私有 `wa2-runtime-progress.json`，在普通宿主轮询边界合并发生变化的文件活动，每 500 ms 最多一次、每次运行最多 64 次；无变化不重写。临时文件关闭后原子替换，写入失败重试且不影响游戏错误状态，日志接收失败也不改变游戏。记录仅含 I/O、资源和调度计数，没有画面、输入矩形、存档或资源内容，不写所选游戏目录。阶段记录标为 `complete:false`，启动页和无线探针优先读取更新的记录。Android 的 `WA2IO` 日志提供相同的有限计数，诊断可在不接管游戏进程时进行。新诊断不能替代完整游戏兼容与实际首次列表耗时测试。

用户在 0.2.54 重新打开“继续游戏”后确认“明显变快”。本次通过无线只读获取该版本的实时计数，无需退出或接管进程：章节清单建立 3 次、命中 198 次，通用清单命中 447 次，无枚举回退；普通元数据查询 20 次、目录枚举 18 次、描述符打开 21 次，其中 16 次使用预解析地址。到最新阶段快照时，元数据、枚举和打开分别累计 228.034、273.516、111.880 ms，合计 613.429 ms。这证明批量查询和预解析打开已在实际程序路径中生效，配合用户反馈确认首次列表有改善。计数覆盖本次运行到该快照，并非从点击到列表出现的独立墙钟计时；不能用它与旧版整次退出记录直接计算倍数，也不代表完整剧情兼容或整体帧率。
