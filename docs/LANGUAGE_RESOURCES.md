# 游戏语言与字幕设置

`0.2.67-shared-aot` 新增独立的 **English** 游戏资源配置：脚本读取根目录
`en.pak`，字库读取根目录 `fon_en.pak`。启动器界面语言与游戏语言分别设置；
英语界面不会自动选择英文游戏资源。默认游戏语言仍为中文。

`0.2.60-shared-aot` 将安卓启动页的自定义脚本、字库选择合并为“游戏语言”。
默认简体中文，玩家可切换日本語，程序自动使用对应资源与内置姓名：

| 游戏语言 | 根目录脚本 | 根目录字库 | 内置姓名示例 |
| --- | --- | --- | --- |
| 简体中文（默认） | `ck-gal.pak` | `fon.pak` | 春希、和纱、雪菜 |
| 日本語 | `script.pak` | `fnt.pak` | 春希、かずさ、雪菜 |
| English（0.2.67 起） | `en.pak` | `fon_en.pak` | 日文基础姓名，后续由补丁脚本设置 |

将对应的原版 PAK 放入选择的资源目录根目录，并保留原有 `IC` 子目录。
游戏目录的名称不限。启动页只需选择语言，不再分别设置文件路径；下次启动
游戏时生效。缺少对应文件会显示具体文件名，不会悄悄改用另一种语言。
这项选择控制剧情脚本、字库、默认姓名与已适配的内置提示，并不自动翻译
图片中的菜单文字。

`0.2.69` 修正了日语、英语模式读档确认文字乱码：这些文字内置在共用程序
中，之前仍使用中文编码，切换字库后便会显示错误字形。现在普通/快速读档、
覆盖存档、存读档完成和恢复默认设置等七处提示按游戏语言初始化；日语
恢复原文，英语使用配套字库能显示的英文。只替换已核对地址与容量的文字
数据，保留静态游戏代码、字形范围表和存档。中文模式保持原内容。两种
内存后端均做组件检查；这些检查不等于已经确认手机上的完整画面效果。

## English 补丁资源

启动页选择 **English**，或在 Windows 命令中使用 `--language en-US`。
根目录需同时保留 `en.pak`、`fon_en.pak` 和原版 `script.pak`，以及完整游戏
资源与 `IC` 子目录。`en.pak` 的脚本优先；缺少的基础脚本数据从原版
`script.pak` 读取，不会转用中文 `ck-gal.pak`。

已检查的英文补丁是包含 `bak`、`fnt`、`grp`、`script` 目录标记的 KCAP。
共用资源适配器按目录范围匹配脚本及背景/界面图片，避免同名文件跨组混用；
英文图片未覆盖的部分仍由原版包提供。原有 `patch.pak` 的优先级保留，
因此其中的内容也需要与所选语言相容。运行时只索引并按需读取外置 PAK，
不解压整个包、复制到 APK 或建立私有资源副本。

字体独立使用 `fon_en.pak`，必须包含游戏原格式的四张字图。如果英文补丁
把配套字图放在 `en.pak` 的 `fnt` 分组中，可以在电脑上生成该文件：

```powershell
python scripts/prepare_english_font.py --root "D:\Games\WHITE ALBUM2"
```

工具直接复制压缩的字体成员到同目录 `fon_en.pak`，不解压字图，不改变
`en.pak` 或原版 `fnt.pak`，也不覆盖已经存在的 `fon_en.pak`。把生成的字库
与补丁 `en.pak` 一起复制到手机游戏目录即可；不要只把 TTF 文件改名。

`0.2.68` 在启动时对照 `en.pak/fnt` 的四张字图索引，检查 `fon_en.pak`
对应成员的压缩标志与保存长度。发现混用字库时会明确报错，避免把改名的
中文字库当成英文使用。该检查只读索引，不整包散列或解压；不是完整内容
校验。自行重新压缩过的字体也可能长度不同，当前请使用上述工具生成配套包。

已检查英文补丁的小号字图是 1920×144 的 32 位真彩，阴影是 1×1 透明图；
原日文/中文字库的小号图为 1920×2304 的 8 位索引图。字形编号相同不代表
两份字体内容或尺寸可混用。按对齐后的绘字函数、常量和调用入口比较，目前
未发现需要修改基础字形索引或 80 列图集网格的证据；EXE 的全局数据地址
迁移不能直接复制到现有 AOT 内存布局。

对提供的英文 `WA2.exe` 进行静态检查后，确认两张字形范围表、字形索引
函数及 32 个初始姓名槽与日文基线一致。English 使用同一套日文基础姓名
与原字形映射；翻译脚本仍可通过原有命令设置姓名。这不代表所有英文补丁
改动已经自动移植；EXE 中的其他布局、菜单等变化仍需分别适配和实测。

`0.2.67` 的 v7 启动配置增加 English 枚举值。旧 v5/v6 配置保留玩家已选的
中文/日文、菜单、字幕及其他开关，旧 v1–v4 继续按既有规则初始化中文。
仍默认开启内置中文字幕，English 不会自动翻译它；可关闭补充字幕或选择
自己的外置字幕。所选语言及路径在下次启动时应用。

## 其他资源与配置说明

从 `0.2.66` 起，游戏语言按钮下直接显示所选脚本包与字库包路径。提示中的
`./` 指玩家已选择的游戏目录，例如日语为 `./script.pak`、`./fnt.pak`。
切换游戏语言后提示立即更新；切换界面语言只翻译提示文字。

三种语言配置由 Windows、Android 共用 C++ 加载层处理：逻辑脚本名
`ck-gal.pak` / `script.pak` 都指向所选脚本，逻辑字库名 `fon.pak` /
`fnt.pak` 都指向所选字库；已有对应 IC 包也使用该资源，不创建不存在的
IC 包。`patch.pak` 的既有优先级保留；其中同名脚本或字图需要与语言配套。
启动时只验证 PAK 索引及必需成员，不把包解压复制到 APK 或私有存储。

日文原程序与已验证的中文 AOT 缓存具有相同的两张字形范围表和索引函数。
区别在于配套字图内容和 32 个默认姓名槽中的 20 个字符串。日语模式只在
初始内存加载后、游戏运行前设置这 20 个姓名指针；代码、字形范围表及
原字符串保持不变。中文版默认不修改姓名。原有配置、存档内已保存的姓名
不在文件中批量改写；切换语言后的旧存档、第三方修改脚本的兼容性仍需实测。

“正篇补充字幕”与游戏语言独立，默认开启并使用内置中文字幕，也可以选择
外置 `sub.yaml`。它只控制语音/音效补充字幕，不隐藏剧情对白或改变语音，
不加入 Special Contents。见 [字幕范围](SUBTITLES.md) 和
[外置字幕格式](EXTERNAL_SUBTITLES.md)。

启动设置保存在所选游戏目录的 `native-launcher.wa2cfg`，后台串行写入。
`0.2.65` 的 v6 记录保存语言枚举、菜单显示偏好、原开关与外置字幕 URI，
最大 4112 字节；仍能读取最大 4372 字节的旧 v3 记录。旧 v1/v2/v3/v4 配置升级时，语言统一
初始化为简体中文一次，不再按旧脚本或字库路径推断日语；包括 `0.2.60`
已写出的日语选择。FPS、长按快进、测试模式和字幕设置保留。迁移成功保存
为 v5 后，玩家手动选择日本語会正常记忆；v5 升级到 v6 也保留该选择，
后续启动不再重置语言。旧记录默认显示右上角菜单，新记录按玩家选择初始化。

损坏配置明确报错，写入失败保留待重试状态。每个资源目录独立保存，切换
语言保留其他开关和字幕来源。回退不支持 v6 的旧 APK 前可备份配置，再让
旧启动器重新生成；游戏存档不因启动器格式升级而转换。

Windows 使用相同的语言配置：

```text
WA2_SDL2_x64.exe --root <游戏资源目录> --language ja-JP
WA2_SDL2_x64.exe --root <游戏资源目录> --language en-US
WA2_SDL2_x64.exe --root <游戏资源目录> --language zh-CN --no-chinese-subtitles
```

省略 `--language` 默认中文。旧 `--script-pak` / `--font-pak` 参数明确拒绝，
提示改用语言选项。不支持的语言也明确报错；这里没有通用翻译或 TTF/OTF
剧情字体替换功能。

补丁作者可以选择以下两种资源对接方式。前提是资源格式与字符映射兼容，
补丁所需的 EXE/DLL 行为也已在共用代码中适配；文件名只决定加载位置。

1. **沿用现有资源名覆盖。** 将译文脚本和字库制作成兼容的 PAK，并使用
   启动页显示的文件名。例如日语配置需要根目录 `script.pak`、`fnt.pak`，
   玩家备份后用补丁包覆盖对应文件，再选择该配置。散文件目录不能直接
   改名为 `.pak`；包索引、脚本成员和字体图集也必须符合现有格式。
2. **保留补丁自己的命名。** 作者提供资源包名称及相对目录，例如根目录
   `script-uk.pak`、`font-uk.pak`，由维护者新增对应游戏语言配置并映射路径。
   有完整构建输入的作者也可自行修改共用语言配置、安卓选择/校验元数据及
   必需的字体/姓名适配后编译。更深的目录或散文件覆盖还需加载层支持。

自行构建完整 AOT 游戏需要既有生成函数、初始化数据及匹配的构建验证输入，
这些内容不随公开仓库提供。仅克隆公开仓库并修改路径，当前不足以直接生成
完整游戏 APK；前提详见 [构建说明](BUILDING.md)。以上方案也不代表已经
验证任何第三方翻译包。当前预设中文、日文和英文，乌克兰语启动界面不等同于
乌克兰语游戏资源配置。

补充字幕可单独自定义，不要求改写剧情脚本包：在启动页的字幕来源中选择
UTF-8 的 `sub.yaml` 格式文件。它按音效 ID，或场景编号与语音 ID 匹配音频，
`begin` / `end` 使用相对该段音频开始的毫秒。作者可参考现有字幕模板翻译
`text`，保留与实际音频对应的编号和时间；每次启动会重新校验。自定义文件
替换整份内置补充字幕，不会自动混合未翻译条目。两根分组、缩进、字段和
限制见 [外置字幕格式及完整示例](EXTERNAL_SUBTITLES.md)。主线对白翻译仍由
所选游戏脚本和字库提供，补充字幕来源与游戏语言分别设置。

内存与合成文件检查覆盖三套资源配对、目录别名、原文件 API、无效选择不
发布、32 个默认姓名槽、七处内置提示、旧设置迁移与写入重试。两平台编译
同一份静态游戏源码。组件检查不等于全剧情验证；未启动游戏、操作界面或
读取屏幕。
