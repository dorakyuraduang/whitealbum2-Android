# WA2 共享静态重编译原型

跨平台开发现在遵守 [config/porting_contract.json](config/porting_contract.json) 和 [AGENTS.md](AGENTS.md)：所有平台共用游戏逻辑和同一份静态生成函数源码，只在系统、设备和呈现接口处保留平台适配。不能为 Android、Windows 各维护一套游戏实现。

`recompiled/` 和 `generated/shared-aot/` 是新增的共用函数级 AOT 路径，从已有 C++ 指令体及 CFG 生成直接分支、直接函数调用和带目标检查的本地跳转表，不打开原 EXE，不链接运行时译码器或 JIT。`scripts/verify_shared_aot.py` 先对照旧指令体检查寄存器、标志、浮点状态、内存、预算和故障，再用真实 Android NDK 链接同一份源码，并比较两次构建实际编译的源文件清单。指令级对照实现只进入测试程序。

当前代码版本为 `0.2.38-shared-aot`。Windows 和 Android 宿主入口均使用共享 AOT 路径；1692 个已接纳入口合并为 1381 个本地函数体，覆盖 119649 个指令位置。仍有 181 个未接纳函数入口及未建立的语义边界，完整游戏流程未验证。`generated/shared-aot/manifest.json` 记录覆盖和未知行为，`logs/shared-aot-verification.json` 绑定实际检查的源码与产物；实际交付版本和哈希见 `out/build-info.json`。

`0.2.38` 增加安卓启动页“长按快进”开关，默认开启、修改即保存。触摸适配使用系统长按时限，将静止单指长按映射为原有 Ctrl 按住；抬手、拖动、增加手指、失焦和暂停释放输入。关闭时，静止长按在松手时只提交一次普通点击。物理左右 Ctrl 和触摸请求合并为同一逻辑按键，单个来源释放不会取消其他仍按住的来源。游戏逻辑和生成静态函数继续两平台共用。

游戏 Activity 在子 View 拆分触摸流前识别双指轻点，包括右上角菜单按钮区域，切换按钮显示/隐藏；菜单状态更新保留本次会话的可见性选择。有效双指手势不先发送游戏/按钮点击；三指、拖动、双指长按和替换第二根手指不切换。菜单按钮自身排除长按快进，原生设置对话框继续处理自己的输入。识别器保留一个待提交 DOWN，拖动或普通松手时交还标准 Android/SDL 输入路径；长按只设置一个时限和按键边沿，不增加逐帧手势轮询。

生产策略的纯 JVM 检查包括 289 条手势轨迹、76 个双指轻点、69 个取消/释放及 288 个物理/触摸 Ctrl 来源顺序，覆盖手指 ID 与先后抬起、时限/移动边界、延迟定时器和被系统合并的移动松手。Activity 与启动页针对官方 API stubs 编译，继续核对 SDL JNI 导出。没有创建或操作 Android View、运行游戏/模拟器、读取屏幕；这些检查不证明手机实际触摸分派和磁盘保存效果已验证。

`0.2.37` 修复安卓点击版本信息时的 `Unsupported source static style 3`：该样式实际是 `SS_ICON` 图标，先前安卓工厂只处理文字/边框静态控件，且序列化遗漏了控件标题中的图标资源编号。共用窗口模型现在从已有缓存的 RT_GROUP_ICON/RT_ICON 解析对应的 32 像素 BGRA32 图像，完整传递原始 DIB；安卓使用 ImageView，保留 Alpha 或旧式透明掩码，不改成桌面启动图标。未知样式、缺少资源或不支持的格式仍明确报错。反复窗口检查还发现已销毁窗口的旧排队消息会中断后续模态循环；分派时仅忽略已知退役窗口的消息，不调用旧过程。

图标检查覆盖两个缓存版本窗口、六种资源尺寸选择、截断和非法图像；实际 Unicode 序列化独立核对图标字节。纯 JVM 运行实际样式分类和解码器，以独立 Python 转换核对两个图标的 2,048 个像素，检查透明/半透明、掩码和自底向上的行。共用内存宿主执行 64 次版本窗口的打开、命令和关闭。先前控件所有权检查用占位对象，不能证明实际控件类型已实现；当前也不把内存检查当作手机 UI 实测。没有启动游戏、模拟器或读取屏幕。

`0.2.36` 继续处理文字与原生精灵计算。字体范围表每次完整核对 256 字节，变化后生成全部 65,536 个代码的直接索引；保留未排序/重叠表的首个匹配、终止标记、非法后续区间和未找到代码的原处理。不变字形增加最多 128 项、每项最多四个图块的精确几何复用；逐字节核对当前 Sprite、图片描述、调色板、半像素常量及全部纹理句柄，不缓存系统对象、指针或像素，仍实时解析目标、混合与采样状态。新字形首次只登记 256 字节输入，重复后才保存完整图块；旋转字形保留原计算。两项缓存合计约 0.5 MiB，使用时才分配，分配失败不阻止原静态路径。

原生精灵中的普通浮点检查改为按 binary32 位模式分类，保留正负零并继续拒绝 NaN、无穷和非零非正规数。对大块字节的“是否相同”检查使用有界整数归并，不依赖体积取向运行库的逐字节词典比较；同时用于既有几何缓存的整数/x87/输入检查及着色器常量检查。既有几何缓存首次观察新的计算时，不再复制完整的六千余字节临时帧；再次观察才保存当前完整输入并计算，失败或取消不发布结果。快进时持续变化的文字仍经过原计算与错误处理，不缩短游戏等待或减少绘制内容。

检查包括 26 份字体表的 1,703,936 个代码、256 次表变动、932 个几何键变动、517 个图块结果、512 次不保存完整结果的新字形，以及 31,322 个字节比较边界案例。实际静态字形入口保留 12 种场景并新增 16 个连续变化场景，核对原始顶点字节、调用 ABI 和无遗留旧图块；同一程序内可关闭新增几何复用作对照，开关与计数只进入诊断构建。精灵路径新增 12 组 NaN、无穷和正负非正规数拒绝。`scripts/compare_glyph_cpu.py` 将同一检查目标文件分别链接已验证的 `0.2.35` 和当前库，交错五轮，记录原生文字、连续换行、静态几何及精灵的有界 CPU 结果于本地 `logs/performance-glyph-extreme-0.2.36.json`。未运行原版、游戏、模拟器、画面或设备，不能据此声称整段快进或安卓帧率已达到某个倍数。

`0.2.35` 继续减少切换资源时的 CPU 解压开销。前置长度校验在范围充足时，一次读取 8 个匹配标记的长度，省去逐标记边界判断，仍拒绝同样的错误输入并保留报错文字。解压在已产生完整 4 KiB 历史且输入/输出范围充足时，先检查一组 8 个标记是否都是连续的 18 字节匹配、引用相同的 1/2/4/8/16 字节重复模式；全部核对后一次写入 144 字节。普通压缩流、初始字典、短尾和不匹配的最后一个标记仍执行原路径；输出、最终字典、调用者尾部依赖、标志返回值以及错误前缀均保留。特殊处理移出普通解码循环，避免扩大其热指令区域。Windows 与 Android 编译相同资源核心，不增加缓存上限，不预先解压或重打包 PAK。

`tests/lzss_groups.cpp` 检查 945 组完整输出/字典/标志和 260 组错误，覆盖全部 256 个 literal mask、环形历史回绕、长度与距离边界、近似模式拒绝及保护字节。对照工具将与 `0.2.34` 已验证结果相符的旧源码仅改名命名空间，以相同 O3 编译；失败时还比较整个目标缓冲（包括已被旧实现写入的推测字节）、异常文字和未提交的字典。六类自建流交替进行五轮有界 CPU 计时，结果保存在本地 `logs/performance-lzss-groups-0.2.35.json`。加速只适用于被接纳的重复模式，普通混合流仍接近原开销；未读取原 EXE、运行游戏或测量实际 PAK I/O、GPU 与手机整段快进，不能据组件倍数承诺整机倍数。

`0.2.34` 针对玩家报告的 `Native widgets: java.lang.IllegalArgumentException: Unknown control token` 修复安卓控件同步路径。旧实现只在首次创建时登记 View，后续完整状态更新遇到缺少的 token 就终止。现在初次创建与后续更新都经过同一套完整状态同步：先验证唯一 token 和结构，构造并登记缺少或身份已变的控件，移除已过期的控件，再设置文字、启用状态和选项；未变的控件保持原 View，避免重置输入焦点。工厂失败或无效状态不能发布半份登记表，未知类型和非法定义仍明确失败。菜单、控件及对话框取消回调只对当前窗口对象和当前 Activity 代次有效；`detach` 只清理它实际所属的 Activity，已排队的旧任务不会重建或更新新会话窗口。游戏逻辑、共享 C++ 和静态函数源码不变。

新增纯 JVM 检查执行实际用于适配层的控件登记与会话类，包含 389 个断言、64 次重复打开、9 种 Activity 会话变化，以及 7 份缓存对话框的 53 个控件；检查缺少 token 时的完整同步、稳定复用、替换/删除、重复拒绝、失败原子性和旧任务失效。此前的 416 次文字往返检查继续保留，但文字序列化校验不能覆盖原生控件生命周期。没有启动 Android 运行时、游戏或屏幕操作，未在手机上复现玩家的具体触发步骤；这些检查不能当作玩家真实 UI 流程已验证。

`0.2.33` 修复安卓系统菜单和设置文字的确定性编码错误：旧适配先把 UTF-16 编成 UTF-8，再用面向原始字节的 `wr::quote` 将每个非 ASCII 字节写成 `\u00xx`，Java 的 JSON 解析器便会把它们当成多个错误的 Unicode 字符。新的 `platform/window/widget_json.hpp` 直接转义原始 UTF-16 单元，菜单、控件、列表、设置标题和文件选择框共用；补充字符保留代理对，控制字符、引号与反斜杠正确转义。原有二进制诊断/生成器的字节转义函数不改动，游戏函数源码和命令逻辑不变。右上角功能菜单按钮由 48 个物理像素改为 48 dp，并清除默认文字内边距，避免入口在高分屏上被挤成小点。

`tests/widget_unicode.cpp` 产生真实适配所用的 JSON 数据，独立 Python JSON 解析器逐 UTF-16 单元核对 416 次文字往返，覆盖 77 组输入、全部 65,536 个单元、中文、日文、特殊字符、路径、代理对和孤立代理单元；旧编码方式的三组失败可在内存中稳定复现。还检查缓存中的 2 份菜单和 7 份对话框，核对包含合成边界项在内的 67 个菜单项、53 个控件的文字及原始 ID、状态、层级和参数。Java/JNI 与两平台均重新编译；只有二进制和既有成功报告哈希都完全相同的静态函数测试才可复用历史内存结果。没有启动游戏或读取屏幕，未声称手机上的实际布局和字体效果已验证。

`0.2.32` 继续减少快进时的资源和等待开销。通用加载 `0x458050` 与解码 `0x457010` 在连续内存中将解压结果直接写入最终分配，省去完整的已解压临时向量、清零和后续复制。压缩输入仍保留独立快照，先完成长度验证，再执行旧文件游标更新和分配回调；分配回调改写输入、改变映射，以及输出槽与输入/结果别名时仍保留原行为。分页或映射不满足直接访问时使用检查过的复制。零字典、末尾 NUL、分配失败及晚期权限故障的已写前缀均不改变。此项不增加资源缓存上限，也不把资源解压后打入 APK。

等待服务的一至四个事件/锁引用改用栈上存储，大集合只分配一次。重复句柄检查改为排序栈上的副本，保留调用者的 wait-any 顺序；多对象调用的句柄列表也改用固定有界存储。512 次常见调用的堆分配分别从 1,536 或 5,120 次降至零，64 对象调用从 40,448 次降至 512 次；未缩短 Sleep、等待截止时间或改变线程执行片。24 位纹理在实际上传前还复用已有 BGR→RGBA 批量模块，避免再经过通用像素格式分派；超出既有 64 MiB 原生转换范围的纹理保留旧处理。

`tests/resource_loading.cpp` 用自建 KCAP/LAC、分页/连续内存检查 64 个完整输出、22 个失败、8 个快照/别名及 2 个分配映射变化；`tests/wait_probes.cpp` 检查 13 个顺序、消费、互斥、错误及真实非零时限案例，并统计 API 内堆分配。旧版与新版对照链接同一检查目标文件，使用三组自建 2 MiB 数据并交错进程顺序；结果保存在本地 `logs/performance-fastforward-0.2.32.json`。它不测原版 EXE、实际 PAK I/O、GPU、整段快进或手机帧率，不能据此声称整机获得同等倍数提升。

`0.2.31` 优化不缩放、无色键的普通图片传输。源为 24 位 BGR 或四种 32 位颜色顺序、目标为 32 位 CPU 图像且未被 GPU 修改时，在读取完整性和地址/页边界验证后直接写入目标矩形；连续内存无需整图暂存，分页内存只使用一行临时缓冲。目标矩形之外的字节和源行间填充均不修改；源晚期故障先于目标写入，且不要求读取矩形之外的源填充。已有 CPU 表面复制也复用原生颜色转换，24 位到 32 位不再经过通用的逐像素采样与格式分派。GPU 已修改的目标、缩放、色键、调色板及未接纳格式继续保留原路径；解压缓存和 PAK 的存放方式不变，两平台使用同一实现。

`tests/image_upload.cpp` 对照 320 组颜色/裁剪/行跨度输入、4 个晚期源故障、4 个不可读填充案例、10 次无副作用拒绝和 12 组 24 位重叠缓冲，另保留已有 176 组像素转换检查。五轮 1920×1080 图像组件计时仅比较先整图暂存再逐像素转换的 CPU 参考流程与直接传输；参考文件按旧呈现源码相同的 O2 编译，核心转换使用 O3。它不测 PAK I/O、GPU、完整加载或手机帧率。

图标方面，原 PNG 确有 8,444 个全透明像素和 906 个部分透明像素，四角 Alpha 均为 0。先前只校验颜色值的做法不能证明桌面透明：Android 的 [AdaptiveIconDrawable 绘制实现](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/master/graphics/java/android/graphics/drawable/AdaptiveIconDrawable.java) 会先填黑色。现在普通和圆形图标都直接引用原 PNG，移除 adaptive-icon XML、前景包装和背景色资源；不修改图案。APK 检查明确验证图标引用和 Alpha，而非仅检查透明色值。部分系统桌面仍会通过 [图标工厂](https://android.googlesource.com/platform/packages/apps/Launcher3/+/5cd4333b5c62b249d3f0b52020864bb9598f92c9/iconloaderlib/src/com/android/launcher3/icons/BaseIconFactory.java) 包装普通图标，不能保证所有桌面都不另加底板；没有启动设备或读取屏幕。

`0.2.30` 修复资源缓冲操作的批量范围过小：普通 REP MOVS/STOS 和 128 字节清零循环原先只接纳最多 1 MiB，大图的其余部分仍执行逐元素访问及 SIMD 兼容封装。上限改为与图片原生处理一致的 64 MiB，在完整验证源、目标、页权限和地址边界后执行；新增倒序且不重叠的 MOVS/STOS 批量处理，最终指针仍按原方向更新并保留允许的末尾回绕。重叠、跨越地址边界、不支持的段、预算检查和故障路径沿用原精确实现。清零快速入口移到原跳转前，校验跳转与循环的缓存签名，不在回边反复预检。Windows 与 Android 继续编译同一实现。

`tests/native_memory.cpp` 检查两种内存后端的 16 组大块操作、16 个保留部分写入的权限故障、10 次真实静态清零函数的恢复调用、16 次拒绝及 8 次单次回退；对照完整寄存器、标志、浮点/段状态、内存、故障位置和代码版本。原 SIMD 存储会规范化 FXSAVE 保留字段，原生清零也保留这项效果。另将同一检查目标文件链接到已验证的 `0.2.29` 库和当前库，五轮交错运行四项 4 MiB 操作、每次两遍，逐字节核对预期输出并比较最终 CPU 状态。最终本机组件计时中，正向/倒序复制中位数约从 39.1/39.7 ms 降为 2.0/2.0 ms，填充从 20.5 ms 降为 0.28 ms，静态清零从 6.4 ms 降为 0.30 ms；对应配对提速约 20.4/21.0/73.4/21.0 倍。原始记录在本地 `logs/performance-native-memory-0.2.30.json`，不读取资源或创建设备，不代表整段快进或安卓帧率已按相同比例提高。

`0.2.29` 修复共用播放器的音视频积压上限。无窗口复现中，对外部 82,567,113 字节的 `mv100.pak` 持续请求音频，旧读取器仅得到 44 个音频帧，读取 8,847,360 字节后便报 `original movie interleave exceeds the compressed packet limit`，缓存已达 8,330,987 字节。共用 Player 现在为两个轨道使用各自的固定游标，只打开对应解码器；非目标轨道在解码前丢弃，不累积另一轨道的包。两个游标仍按位置读取同一个外部 Source，不复制或解压整个视频到内存、落盘或 APK。压缩数据可能被两个游标分别读取；这项修复不声称降低总 I/O。普通按文件顺序的 Reader 保持原有接口，非法或被排除的轨道显式报错。

`0.2.12` 将热点整数寄存器转为 C++ 局部值，依据缓存 CFG 固定顶点计算的浮点槽位，并对关键计算强制内联；同时加入有次数上限的系统接口及间接静态函数直连、按页缩小恢复入口查找范围、批量读取 API 参数、复用有界诊断记录、按页扫描字符串和空闲调度减负。绘制 CPU 组件的配对线程周期减少约 26%–34%；该结果不代表整个游戏达到 10 倍或手机达到 120 帧。32 位游戏数据布局、ABI 状态及受检查地址空间仍然保留，部分浮点运算仍使用软件扩展精度实现。

## 性能优化与复测

默认使用构建时生成的 x64 汇编。151 个代码页之间的分支、调用、返回可在同一次原生执行中连续完成；寄存器、标志与 x87 状态保留在硬件中。稀疏 4GB 地址空间保留原游戏的 32 位数据布局，内存权限、代码证明失效、精确故障位置和诊断指令预算仍受检查。未覆盖的指令形式执行已有 C++ 指令体，不进行运行时解码或 JIT。

热点排序在原代码证明、内存预检和有序性检查通过后使用二分查找，按原循环的分支、查找和移动次数计算指令预算，只提交完整的循环迭代。重复键、负数键、30000 哨兵、预算不足、不可读页、只读目标、可执行栈和代码变更均与原指令体对照。验证通过的页描述符用于直接访问数据，避免每页反复查找通用区域表。

渲染状态、采样器和有效纹理令牌可在原生汇编内更新，涉及资源寿命或宿主调用时回到检查过的桥接。固定功能绘制按状态批量提交；上传只复制请求区域，DrawPrimitiveUP 的解码与暂存空间重复使用。离屏对照覆盖 D3DX NONE/POINT、色键、透明度、纹理朝向、视口、裁剪与着色器，不读取游戏窗口画面。

协作线程在等待时保留 API 的 PC、栈和返回状态，不再反复抛出异常重试。调度按优先级分配有界配额，主线程按工作线程状态调整检查间隔。休眠使用单调截止时间和高精度等待计时器，有工作线程时每次系统等待最多 2 毫秒，不忙等，也不缩短游戏请求的休眠时间。BGM 的补充缓冲期限和写入时的播放位置单独记录；缺失音频记录、解码超时或写入正在播放半区的样本不能通过性能对照。系统接口按连续的桥接地址直接索引，接口对象单独持有，嵌套回调中注册更多接口也不会使正在执行的对象失效；未对齐地址和未实现接口继续按原规则拒绝。

当前有 13,691 项原生后端对照、15,786 项批处理对照。`scripts/verify_execution.py` 执行 27 项回归，其中图形测试强制 `--offscreen-only`；另有 10 项排除窗口的核心回归。CRT 功能检测直接执行原有 EFLAGS/CPUID/SSE2 探测函数，并核对 765 种执行边界及初始化调用情形，不强行写入功能开关。启动结构测试使用 `--startup-only`，核对本机启动标志、显示方式和 guest 标准句柄，不创建窗口。`GetStartupInfoA` 保留 `STARTF_USESHOWWINDOW`，让后台启动的显示设置传入原游戏 CRT。视频事件测试使用 `--events-only`，不创建窗口，并以原始 `0x44bd20` 函数在逐指令和原生后端分别核对失败事件不会误报播放结束。`logs/execution-suite.json` 绑定 EXE、测试程序和实际链接库的哈希。这些检查比较寄存器、全部标志、完整浮点状态、内存、预算和异常位置，不代表完整剧情已测试。

整程序测速关闭指令采样和画面读取，不发送输入，也不控制前后台。`scripts/benchmark_native_runtime.py` 在固定 125 秒后终止自己启动的子进程，记录 Present 计数、前后台状态、CPU 时间、休眠耗时和音频事件。原版使用只针对自启动 PID 的 PresentMon ETW。两版使用同一批硬链接资源和相同配置，并保留测量前后的配置快照；稳定区间统一从第 30 次 Present 起算。GetEvent 无事件时保留失败 HRESULT，并将输出事件码和参数清零，避免游戏读取残留的 EC_COMPLETE。新版开场动画未自然完成的样本会被拒绝，前台和后台结果分别记录，不能互相替代。两版测速的 `--background` 使用进程启动参数 `SW_SHOWNOACTIVATE`，不在启动后调用焦点切换或发送输入，最终分类仍以实际状态计数为准。

`scripts/compare_original_native.py` 复算计数和哈希，输出 `logs/original-native-performance.json`。普通启动另用 `--ordinary` 复测，不传原镜像、诊断帧数或预算参数，并核对资源目录 EXE 与构建产物的哈希。`out/build-info.json` 只收录哈希匹配当前产物的证据。Present 事件不能证明画面完全一致，定时停止也不能作为正常退出证明。旧截图、5.33 FPS 等历史结果保留在各自日志中，不作为本版性能或画面的证据。

上游运行时修改保存在 `patches/winrecomp-wa2.patch`。`scripts/refresh_runtime_patch.py` 从保存的上游源码包重新生成补丁，并在独立目录应用、逐文件核对，证据为 `logs/runtime-patch.json`。上述执行器属于现有 Windows 兼容版；正在重建的 Android ARM64 引擎使用独立的原生函数、资源与脚本模块，当前工作是补齐实际剧情流程。

## 资源周转与发布包

小块 `HeapAlloc` 使用 64 KiB 内存池，按 16 字节对齐分配；空池释放，大块仍使用独立区域。`HeapSize` 保留请求长度，重分配保留原数据，并检查固定堆预算及原地扩展限制。堆预算采用累计计数，虚拟分配按已有区域跳过占用范围，避免每次从头逐个试探 64 KiB 地址。对齐、清零与失败后保留旧块的契约参考 [HeapAlloc](https://learn.microsoft.com/en-us/windows/win32/api/heapapi/nf-heapapi-heapalloc) 和 [HeapReAlloc](https://learn.microsoft.com/en-us/windows/win32/api/heapapi/nf-heapapi-heaprealloc)。

图形资源的弱引用索引定期删除失效项，纹理表面直接从对应图像查找，避免遍历整个历史记录。声音诊断区分缓冲区生命周期，并只保留当前对象及最近 32 个已释放缓冲区。`guest_allocations`、`sdl_resource_lifetimes` 和音频报告提供当前数量。压力回归覆盖 32,768 个并发小分配、随机释放、大小块迁移、4,000 次复用、200,000 次弱引用周转、6,000 次离屏纹理创建上传释放，以及 256 次不同长度声音缓冲区的地址复用。这些检查不读取游戏窗口，也不代表实际剧情快进已经验证。

默认仅链接线性内存的原生汇编；线性内存不可用时使用已有的静态 C++ 指令路径。开发选项 `WA2_PAGED_NATIVE_BACKEND=ON` 可恢复额外的页表汇编后端，但会增大 EXE。`scripts/stage_runtime.py` 将 PDB 调试符号放到 `build/symbols/`，早期的 `WA2_x64.exe` 和对应 PDB 保存在 `build/legacy-output/`，运行资源目录只需要新版 EXE 与原有资源。

`port/native_resources.cpp` 负责旧调用约定：在 `0x4588a0`、`0x458050`、`0x457010`、`0x437000`、`0x437220`、`0x437310` 进行一次参数/结果转换，调用完整查找、加载和两种解压函数。`port/native_vorbis.cpp` 将构造 `0x4566d0`、清理 `0x456700`、格式查询 `0x4567b0` 与解码 `0x456930` 全部交给普通音频模块。`port/native_functions.json` 列出十个完整函数，生成器移除对应重复汇编，共 1,488 个可翻译指令位置。资源入口仍保留异常布局的检查路径；旧音频实现只保留在测试程序中。

`port/retired_modules.json` 列出旧 Ogg/Vorbis 库 `0x4616c0..0x474330` 的边界、四个替换入口和回调表。构建检查同时核对 CFG 直接入口、解码后的绝对引用、对齐的回调指针及表的外部使用。正式版链接 `compact-fallback/release/` 的代码，测试链接完整对照代码；旧 MDCT/复制内核独立放入 `wa2_codec_oracle` 测试库。通用浮点表在正式版中额外移除 147 段旧音频辅助代码，剩下 347 段；辅助函数采用独立 COMDAT 供链接器剔除。`logs/retired-modules-verification.json` 记录源文件哈希和删除范围，包体检查确认正式链接未带入对照库。没有凭短时间运行中“未观察到调用”来删除这些函数。

`engine/vorbis_stream.*` 使用固定版本的 [stb_vorbis 1.22](https://github.com/nothings/stb/blob/master/stb_vorbis.c)，以普通字节缓冲区接收 Ogg 数据、输出交错的 16 位 PCM，不依赖虚拟 CPU、Windows、SDL 或文件 API。格式查询只解析 58 字节识别页并校验 Ogg CRC，不创建旧解码器或分配其缓冲。输入队列限制为 4 MiB；小输出缓冲采用部分接收，明确区分暂时排空与输入结束。解码器、压缩数据和剩余 PCM 均归流对象所有，循环播放创建新流，不复用上一轮已消费的数据。适配层维持格式缓存、调用约定、结束返回值与音频播放缓冲接口；无连续兼容地址空间时使用受检查的字节复制，仍由同一个普通 C++ 解码器处理。

非循环文件的结束分为“已输出最后数据”和“后续空请求返回停止”两步；后者释放原生流并返回原来的零结果，避免持续空转。`native_vorbis.requests` 包含所有调用，`exhausted_calls` 单独记录空输入的终止处理；普通启动检查同时限制两者，不能只用“没有异常”和已播放前半段来判断结束逻辑正常。

标题 Logo 开始渐变时，旧路径会在主线程连续读取数块 BGM 并同步解码，原有后台计时多次记录约 44–46 ms 的首帧间隔；其中纹理上传约 1.7 ms，画面交换约 0.05 ms，文件读取本身没有对应的长等待。新路径将整段解码交给原生模块。`scripts/trace_logo_fade.py --frame-trace` 只记录自己的帧阶段、较大四边形的透明度和资源计时，不抓取画面、不注入输入。临时的全接口/CPU 采样已撤除；帧明细仅在 `WA2_FRAME_TRACE=1` 时启用。

`logs/logo-fade-verification.json` 绑定同一发布构建的两轮复测：检查 Logo 首次提交间隔及 `4,8,12,17` 的初段透明度步进，记录每轮实际前后台与最小化状态，仅在状态一致时直接比较历史耗时。修复前的后台首帧间隔为 46.2961 ms，修复版首次两轮后台记录分别为 7.9805 ms 与 8.7212 ms；后续发布重新绑定各自构建的复测记录。测试不改变焦点来制造一致条件。这里验证的是程序提交和动画数据，不是屏幕刷新、肉眼流畅度、整段剧情帧率或手机性能。

`wa2_native_vorbis_tests` 对比三首真实 BGM 的完整旧解码函数与原生输出，另以三个真实语音成员补充单声道比较，检查长度、样本误差、格式查询及缓存、构造清零、重复清理、两轮播放、输出边界及不同输入/输出分块；无连续兼容地址空间时的输出也一致。旧对照实现的耗时不是原版游戏进程的性能。浮点实现不同，不能称为逐字节相同；测试报告保留最大及均方根样本误差。`wa2_vorbis_stream_tests` 独立链接普通引擎/平台模块，检查分块、EOF、非法输入与内存上限，并核对本机 BGM、SE、VOICE 三包中 39,009 个未压缩 Ogg 识别头。

`platform/clock.*` 用标准 C++ 单调时钟和系统时钟实现性能计数器、毫秒时钟及日期时间。`platform/timer_resolution.cpp` 隔离系统计时精度策略；Windows 后端负责成对请求/释放，其他系统使用各自调度计时。旧 ABI 仅在适配层进行 32/64 位字段转换。窗口、输入、视频、ACM、注册表及其他接口仍有 Windows 实现，不能将这几个模块的完成视为全程序跨平台完成。

可独立构建 `cmake -S engine -B build/portable-native ...`，该工程只链接引擎、通用平台模块和当前系统的计时策略，不链接兼容执行器、SDL 或 DirectX。`ctest --test-dir build/portable-native` 执行 PCM、资源和 Vorbis 三项检查。资源、文件、时钟与 Vorbis 源码均通过 ARM64 Linux 对象交叉编译检查；仍需完整 Android 构建和设备运行才能确认安卓支持。当前 EXE 的大小以 `out/build-info.json` 和 `logs/package-size-verification.json` 为准，仍比 1,220,096 字节的原 EXE 大；后续体积缩减需要继续重建剩余引擎函数。

`scripts/inspect_binary_size.py` 从匹配 GUID 的 PDB 读取节贡献，分别核算 EXE 文件字节与映射字节，不将 BSS 当作磁盘包体。浮点辅助函数分别放入可剔除的 COMDAT；发布链接显式使用 COFF `/OPT:REF`。固定的 Zig 0.15.2 驱动未将 GNU `--gc-sections` 转发到 COFF LLD，`scripts/link_release_pe.py` 复用编译器解析出的相同 CRT/库输入，保留匹配 PDB 并记录真实链接参数与产物哈希。编译器输出参数没有转义，该检查会拒绝不能无歧义还原的文件路径。这个构建清理不增加外部 DLL、不使用 EXE 压缩器、不删除指令覆盖，也不代表移除了虚拟 CPU。

Android 资源位置固定为手机内部共享存储根目录的 `Wa2Res`（主用户通常为 `/storage/emulated/0/Wa2Res`），保留 `Wa2Res/IC` 子目录。首次启动通过 Android 系统目录授权界面授予 `Wa2Res` 的读取权限，此后复用持久授权；其他目录、存储根目录和 `IC` 子目录本身均不作为资源根目录接受。`.pak` 留在原处，通过文件描述符按需读取，资源不会完整解压、转码或打入 APK。目录策略、文件描述符与包名检查记录在 `logs/android-storage-verification.json`，Java 编译记录在 `logs/android-java-verification.json`；目录授权仍需手机实测。

Android 使用 `game/Scene` 作为原生剧情宿主，和无窗口检查执行同一份代码：LSCR 剧本、背景与事件画面、遮罩转场、两种雪花、原版字体对白、8 个角色槽位、32 个普通图片槽位、流式 BGM/SE/语音，以及经用户授权的通用 WMV/WMA 解码库。该执行路径不链接 Windows 接口、原机器码镜像、虚拟 CPU 或逐指令调度。LSCR 是游戏自身的剧本语言；它与 CPU 模拟不同。Windows 发布 EXE 仍沿用旧路径，不能把安卓版的原生重建当成旧 EXE 已完全替换。

`scripts/verify_native_game_scene.py` 从真实 `1001` 脚本进入剧情，让 `IC/mv010.pak` 自然结束后继续执行对白、人物和原包语音；结果、实际推进数量、最后指令及未实现边界记入 `logs/native-game-scene-verification.json`。测试只用自有内存表面，不打开窗口、音频设备或屏幕。它不证明完整游戏、画面完全一致、手机性能或安卓生命周期已实测。后续未实现指令会明确报告，不会跳过。GLES2 遮罩使用原有 `pf00..pf03.psh` 的计算方式，复用合成目标及纹理，仍需手机验证实际显示。

`android/game/game_host.cpp` 接通外部资源、SDL2 渲染/触控、原生音频、暂停恢复及实际提交帧率统计。当前设备开发包直接进入序章 `1001`；完整标题菜单、存读档/回看界面及部分后续命令尚未重建，不能称为完整移植。点击推进对白，长按半秒快进，返回键隐藏/显示对白窗；支持键盘空格/回车及 Ctrl。游戏逻辑保持 60 Hz，画面提交上限设为 120 Hz，HUD 显示实际提交的 FPS/毫秒，不将屏幕刷新率当作游戏帧率。120 Hz 请求不是设备性能保证。

`scripts/build_android.py` 使用本机 SDK/NDK 单任务、低优先级构建；先核对共享剧情、资源目录、Java 和实际 ARM64 链接的当前源码。APK 不包含原版资源或旧执行器，使用 MinSizeRel 与符号剔除，产物记录在 `logs/android-build-status.json`。FFmpeg 对应源码、配置、应用目标文件和可验证的重新链接脚本单独放在 APK 旁的 `WA2-native-relink.zip`，不增加 APK 资源体积。文件目录授权、完整流程和帧率均需要手机实测。

图片解压的实际入口是 `0x437000`，与旧音频/归档读取器的 `0x457010` 使用不同的初始字典：前 4,078 字节分别为空格 `0x20` 与零。部分人物资源会因此产生不同字节，两个入口必须分别校验。独立参考脚本现在生成 `samples.bin`（零字典旧接口）和 `portable-samples.bin`（KCAP 空格字典）。完整图片解压适配器先验证输入与输出长度，再直接将原有连续字节缓冲区交给普通 C++ 解码函数，不复制整份源/目标缓冲区。字典、调试输出和 cdecl 调用约定保持一致；别名、可执行目标页或无效输入保留原检查路径。实际启动报告的 `native_resources.image_decodes` 用于确认图片加载调用了这条新路径。

图片资源的完整读取入口 `0x437310` 和存在性查询 `0x437220` 现在也调用普通 C++ 索引与读取。目录缓存最多保留 8 个资源包，按文件大小和修改时间失效，不缓存完整解压图片。第一次打开资源包只读取包头与目录；压缩成员的长度前缀在实际读取该成员时检查，避免打开包时对每一项进行零散读取。连续的头部/内容读取复用流位置。原压缩数据留在普通字节缓冲区，解码直接写入最终分配，省去原来的压缩数据兼容区及其复制、清零。保留未压缩/空资源、同名条目的第一个物理位置、原分配长度与最终字典状态。可选资源包不存在时直接返回原来的零结果及错误码 2，不改写输出指针，也不回退到原指令函数；实际报告中的 `image_missing_archives` 将其与解码错误分开计数。

LZSS 解码从已经产生的输出复制匹配内容，在目标仍容纳 18 字节且历史距离足够时使用定长复制；提前写出的后续字节会由后续 token 覆盖，历史引用仅使用已产生的有效前缀。接近缓冲区末尾时使用精确长度，最终一次性回写 4 KiB 字典。复制不越过已分配缓冲区，也不要求 CPU 专用指令。2,000 组独立参考用例核对输出、字典、结束标志及边界字节；真实资源仍核对独立 SHA-256。`0x437310` 在尚未发布的最终分配中一次完成长度检查和解码，使用局部字典，成功后才提交输出指针与共享字典，省去完整的解压前扫描。调用者传入可见目标的 `0x437000` 仍保留预校验。六组截断、长度错误及多余输入检查确认失败时不会发布半成品、改写字典或泄漏分配。

`wa2_pak_loading_tests` 对照原来的完整图片加载函数，重复 40 次真实加载，检查缓存失效、空文件及重复名字。`native_resources.single_pass_image_decodes` 确认实际启动使用单遍路径；`timing` 将索引、读取、校验、分配和解码耗时分开，`resource_graphics` 记录后续表面加载。`scripts/compare_resource_loading.py` 绑定已归档的旧测试程序，交替执行三轮新旧解码及完整图片加载，结果保存在 `logs/resource-loading-comparison.json`。该对照不清空文件缓存，不测原版 EXE 或整段场景加载，不能作为手机性能结论。
