# 外置字幕：sub.yaml 与 Todokanai

[English format guide](EXTERNAL_SUBTITLES.en.md)

从 **0.2.70** 起，也支持原 Todokanai `subtitles` 文件。通过同一个文件
选择器自行选择，文件名不限，按内容检测格式；仍默认内置字幕，不自动选择
补丁文件。两种格式均为 UTF-8，最多 1 MiB。

Todokanai 示例（后文的固定 YAML 规则仍原样适用）：

```text
{
1002 9763 1002 114
0 800 First line^Second line
800 900 Next caption
}
```

头部为音频场景、音频编号、PC 剧情场景和行号；后两项作为经过校验的
定位信息，本端按实际音频事件触发。时间行为“开始毫秒 持续毫秒 文字”，
第二个数字不是结束时间。`^` 强制换行；较晚字幕开始时替换仍在显示的
前一条。场景为 0 可匹配全局音效，其余按音频场景匹配。同一文件中的音频
身份不能重复，语法、编码、顺序、时间溢出和容量限制均检查。
这份乌克兰补丁的附带字幕当前为英文，可自行翻译内容后选择文件。

从 `0.2.59-shared-aot` 起，安卓启动页的“字幕来源”可以在“内置字幕（默认）”
与玩家选择的外置字幕文件之间切换。“正篇补充字幕”仍是同一个总开关，
同时控制内置和外置字幕；没有增加第二个字幕开关。默认继续使用内置中文。

这里沿用此前汉化补丁正篇 `script/sub.yaml` 的字段和层级，**没有改成另一套
字幕格式**。程序支持该原文件使用的固定写法，不是完整的通用 YAML 解析器。
最方便的制作方式是复制[原字幕文件](../third_party/wa2_subtitles/sub.yaml)，
保留音频编号、时间和缩进，翻译每条 `text`。

## 如何使用

选择步骤：

1. 点击“字幕来源 → 选择外置 sub.yaml”，在系统文件选择器中选择文件。
2. 等待编码、结构、音频编号、时间轴及字形校验通过。失败会显示原因和
   出错行号（适用于语法错误），并保留原来的选择。
3. 从启动页重新开始游戏。每次启动会读取并重新校验文件；修改后的错误
   不会被旧校验结果掩盖。缺失文件或失效授权会提示重新选择。

字幕文件不必叫 `sub.yaml`，但内容必须符合下面的格式。它可以放在通过
系统文件选择器授权的任意位置，不需要放入 APK 或覆盖原版 PAK。
文件只读；设置和文件引用保存在所选游戏目录的 `native-launcher.wa2cfg`。
系统需支持持久读取授权。取消选择、错误文件和校验失败都不改动原选择。
点击“内置字幕（默认）”即可恢复内置来源。

Windows 使用同一实现，通过参数选择，路径可为绝对路径或相对游戏目录的路径：

```text
WA2_SDL2_x64.exe --root <游戏资源目录> --subtitles sub.yaml
```

省略 `--subtitles` 使用内置字幕；`--no-chinese-subtitles` 关闭当前字幕来源。

## 支持的格式

文件使用 UTF-8 编码，可带文件开头的 UTF-8 BOM，支持 LF/CRLF 换行。
不能使用 UTF-16、GBK 等编码。文件最多 1 MiB（1,048,576 字节）。

下面是可以直接解析的完整最小示例，编号、时间和文字取自原正篇字幕文件。
它只保留两段音频，用于展示格式；不会显示原文件中其余音频的补充字幕：

```yaml
soundEffect:
    - id: 8365
      content:
          - begin: 0
            end: 5000
            text: 峰城广播站
voice:
    - scene: 1008
      id: 166
      content:
          - begin: 0
            end: 3000
            text: 呜哇……
```

### 字段与音频匹配

| 字段 | 含义与填写规则 |
| --- | --- |
| `soundEffect` | 音效字幕分组，按音效 `id` 匹配。 |
| `voice` | 语音字幕分组，按该音频的 `scene` 与 `id` 共同匹配。 |
| `scene` | 语音所属的原始音频场景编号，十进制整数，1–65535。 |
| `id` | 音频编号，十进制整数，0–65535；不是字幕行号。 |
| `content` | 同一段音频内的字幕列表，至少一条。 |
| `begin` | 相对这段音频开始的显示时间，单位毫秒，包含这一时刻。 |
| `end` | 相对这段音频开始的结束时间，单位毫秒，到这一时刻即不再显示。 |
| `text` | 这一时间段显示的非空文字，直接写单行文本，不加外层引号。 |

`begin: 1000`、`end: 4000` 表示音频开始后第 1 秒到第 4 秒之间显示。
每段新音频的计时都从 0 开始；它不是整部影片、整个场景或整个游戏的时间轴。
时间必须满足 `0 ≤ begin < end ≤ 4294967295`，不用 `00:01.000`、小数或秒数。
同一音频内的字幕按时间升序排列，允许间隔和首尾相接，不能重叠。

同一个音效 `id` 只能定义一次；同一个语音 `(scene, id)` 组合也只能定义
一次。不同语音场景可以使用相同的 `id`。同一音频的多句话应放在同一个
`content` 中，不能通过重复音频条目来添加。段落之间的音频条目不要求按
编号排序，程序会在读取后排序。

编号要与游戏实际触发的音频一致。语音在其他剧情中被复用时，仍使用音频
自己的场景编号，不是把 `scene` 改成当前剧情的编号。翻译现有字幕通常只需
改 `text`；新增音频字幕需要先确认其编号和时间，不能自行分配演示编号。
**格式校验只检查结构、编号范围、时间和字形，不检查 PAK 中是否存在这个
音频，也不保证剧情一定触发它。**

### 一段音频显示多条字幕

下面用原文件中的语音编号演示拆成两句话的写法。时间和文字为演示内容，
不表示原语音的译文；制作时替换成实际内容：

```yaml
soundEffect:
voice:
    - scene: 1008
      id: 166
      content:
          - begin: 0
            end: 1000
            text: 第一条字幕。
          - begin: 1000
            end: 3000
            text: 第二条字幕。
```

两个根分组 `soundEffect:`、`voice:` **都必须出现且各出现一次**，可以有
一个空分组。空分组只保留标题，如上面的 `soundEffect:`；不要写成 `[]`、
`{}` 或 `null`。整个文件至少有一段音频，每段至少有一条有效字幕。

### 缩进和文字写法

字段名区分大小写。请按示例顺序写字段，使用普通半角空格，不用 Tab：

| 行的开头 | 行首空格数 |
| --- | --- |
| `soundEffect:`、`voice:` | 0 |
| `- id:`（音效）或 `- scene:`（语音） | 4 |
| `id:`（语音）、`content:` | 6 |
| `- begin:` | 10 |
| `end:`、`text:` | 12 |

冒号后有值时，使用示例中的一个空格；`content:` 和根分组标题后不写值。
不要让编辑器自动改成常见的 2 空格 YAML 缩进，不要在编号、时间、分组标题
或 `content:` 行末增加空格。`text` 值的首尾空格会被去掉。

支持空行与独立一行的 `#` 注释，注释行可以缩进。**不支持行尾注释**：
数值后加 `#` 会导致校验失败；`text` 后的 `# ...` 会作为字幕正文显示。
所以注释请单独写一行。

每条 `text` 在文件中只能占一行。较长文字由当前绘制器自动换行；`\n`
这两个字符会被原样保留，不会转换成换行。不要使用 `|`、`>`、外层单/双
引号、YAML 标签、引用或锚点。普通引号可以出现在文字中间；文字不能以
`! & * { } [ ] | > ' " % @` 或反引号开头，这些开头会被解析器拒绝。
不支持额外字段、重复字段、嵌入文件、`---` 文档分隔符或 Special Contents
分组；也不能直接读取 SRT/ASS，因为它们缺少本功能使用的场景和音频编号。

### 大小限制

| 项目 | 上限或要求 |
| --- | --- |
| 文件大小 | 1 MiB，文件不能空 |
| 音频条目总数 | 1024 |
| 字幕条目总数 | 8192 |
| 每条文字 | 1–512 个 Unicode 码点，不是 UTF-8 字节数 |
| 所有字幕文字合计 | 131072 个 Unicode 码点，重复文字也计入 |
| 不同字符数 | 整份文件最多 1536 种 |
| 控制字符 | 文字不能包含 Tab、换行、控制字符或正文中的 BOM |

## 制作多语言字幕

1. 复制[完整正篇模板](../third_party/wa2_subtitles/sub.yaml)，保留根分组、
   `scene`、`id`、`begin`、`end` 和缩进。只翻译每条 `text`，保存为 UTF-8。
2. 可以将不同语言分别保存为 `sub-uk.yaml`、`sub-en.yaml` 等任意名称，
   启动页一次选择其中一份。当前每次运行只使用一个字幕来源，不自动按
   游戏语言合并或切换多份文件。
3. 在启动页选择文件，等待校验通过并开启补充字幕，再启动游戏确认同步。
   修改文件后需要重新启动游戏；运行中不会逐帧重读文件或自动刷新字幕。

外置文件**替换整份内置字幕**。如果只写了两段音频，就只有这两段显示补充
字幕，遗漏的段落不会自动回退成内置中文。内置数据本身不会被改写，选择
“内置字幕（默认）”即可恢复。

补充字幕来源与游戏语言独立。选择日语剧情也可以使用外置乌克兰语字幕；
它不会翻译脚本中的普通剧情对白、菜单图片或人物姓名，也不会替换游戏的
脚本包、字库包或音频。普通剧情翻译仍需要配套资源与必要的程序适配。
字幕文件无需增加 `language`、`font`、`size`、`position` 等字段，当前解析器
也不支持这些字段。

## 常见问题

| 现象或提示 | 检查内容 |
| --- | --- |
| `sub.yaml line N: ...` | 从文件第一行起数到第 N 行，包括空行和注释。缺字段或时间错误有时指向条目开头。 |
| `unsupported field, YAML syntax or indentation` | 检查字段大小写、固定空格数、行末空格以及是否加入了额外字段。 |
| `expected an unsigned decimal integer` | 编号和时间只能写十进制整数，不能加引号、负号、单位或行尾注释。 |
| `invalid or overlapping time interval` | 检查开始早于结束，以及同一音频下后一条不早于前一条结束。 |
| `duplicate scene/audio identity` | 同一个音频写了两次；把多句话合并到一份 `content`。 |
| `text must be a literal plain string` | 检查是否为空、带外层引号，或以不支持的特殊字符开头。 |
| 提示缺字或字体尺寸不支持 | 当前设备字体不能为这些字符生成可用字形；格式正确也可能在字形校验时失败。 |
| 校验通过但不显示 | 检查补充字幕开关、所选文件、音频编号、实际播放时间，以及本文件是否包含这段音频。 |

本格式说明、示例与当前共享解析器对应。组件校验不等于所有剧情、语言和
设备的显示验证；修改后的音频长度和新的补丁资源仍需作者实测。

## 字体与实现边界

内置中文字幕及字图可覆盖的中文 YAML 内容继续复用原字图。
从 0.2.72 起，外置英文与 Todokanai 字幕保留字体适配器测得的逐字宽度，
字母、标点和空格不再统一占用 28 像素；共用排版按实际宽度居中、优先按词
换行，并保留 `^` 手动换行。字号及行距保持原设置。
需要的平台字图只在内存中生成一次，再交给同一套 C++
排版、描边、播放时序和 GPU 提交。Android 使用系统字体，Windows 使用
Microsoft YaHei；不依赖截图、不读取屏幕。缺字或超过字图尺寸时明确拒绝，
不会以缺字方框代替并宣称校验成功。复杂文字塑形和所有 Unicode 字符的
跨设备覆盖不作保证；Windows 新字形适配器目前支持 BMP 字符。
字图只在需要时上传，不逐帧读 YAML、生成字体或新增 Java 字幕覆盖层。

安卓选择时与实际运行时、Windows 使用同一个严格 C++ 解析器。
启动器只为校验加载本地库，不进入游戏、不打开窗口或音频设备。
外置文件启动时重新读取，验证通过后建立只读播放数据。
`0.2.67` 使用 v7 启动设置，最多 4112 字节；仍兼容最大 4372 字节的旧
v3 记录及 v1/v2/v4/v5/v6 记录，保留字幕来源。不保存字幕正文或字图。
回退旧 APK 前可备份该配置，再让旧启动器重新生成。

组件检查逐条比较原有全部 315 条字幕和 6462 个字符，覆盖 BOM/CRLF、
不合法编码、字段和时间冲突、大小边界、播放器切换、字图和原音频事件桥接。
两平台编译同一份静态游戏源码。没有启动游戏、模拟器或操作/读取画面；
手机字体显示、文件提供者授权与实际剧情同步仍需玩家实测。
