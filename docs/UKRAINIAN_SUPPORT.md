## 已确认的兼容性条件

| 部分 | 静态检查结果 | 接入要求 |
| --- | --- | --- |
| 脚本 | 主目录 186 组、IC 目录 30 组 `.bnr/.txt` | 保留字节和主目录/IC 的独立命名空间 |
| 字符索引 | 两张范围表及全部 65,536 个编号的查找结果，与现有 AOT 一致；查找函数的 100 字节也相同 | 沿用现有索引，不全局重排字库 |
| 大号字库 | 外置的两张 3200×3840、32 位 TGA | 它们覆盖补丁 `en.pak/fnt` 中的对应字图 |
| 小号字库 | `en.pak/fnt` 还提供两张 14pt 字图 | 合并为配套的四张字图，不能使用中文字库 |
| 默认姓名 | 相对日文/英文基线有七个姓名槽改变，其余槽保留基线 | 按补丁实际字节初始化全部 32 槽，保留原有空槽与别名关系 |
| 文本处理 | 相对已分析的英文 EXE，`.text` 有 65 个不同字节，涉及两处引号输出和一处字符推进修正 | 在共用文字处理逻辑中移植这些语义 |
| 界面与背景 | 混合 KCAP `en.pak` 有 `bak/fnt/grp/script` 四组，共 517 项 | 按分组查找，防止跨组同名混用 |
| 补充字幕 | `todokanai/subtitles` 为花括号分块、四整数头、时间行格式，样例内容为英文 | 不能直接作为 `sub.yaml`，也不能当成已完成的乌克兰语字幕 |

补丁的 `.txt` 多数使用单字节字形编码，216 个文件中有 17 个还含高位字节。
它们不是可以任意按 UTF-8 转码的普通译文。应保留原字节、标签和字符串顺序，
由配套字图显示乌克兰字符。

已定位的文字改动如下，地址均为**补丁 EXE 地址**，不能照搬到现有 AOT：

- `0x4452b4` 与 `0x4465f5`：对应的引号处理分支把输出字节从 `0x27`
  改为 `0x60`。这是特定分支的行为，不能全局替换脚本中的撇号。
- `0x446fb2` 跳入 `0x4a087e` 的补丁段：在原字符推进分支中，`0x22`
  的推进值减 5，`0x27/0x3b/0x60` 减 6，然后恢复原控制流。
  移植时需保留所在分支、尺寸与状态语义，不能对所有绘字路径统一减值。
- 默认姓名变化位于槽 `0/1/2/10/11/12/16`。其编码依赖这份乌克兰字库。

## 推荐：一次准备外置 PAK，运行时沿用现有加载方式

拟增加一个离线准备工具，输入作者的原 ZIP，输出两份外置资源：

```text
玩家选择的任意游戏目录/
  uk.pak
  IC/
    uk.pak
  原有各 PAK、存档和配置……
```

`uk.pak` 是包含脚本、字体、界面分组的 KCAP：

1. 以补丁的 `en.pak` 为基础，保留背景、界面和缺失译文的原补丁后备内容。
2. `script` 分组中优先放入 `payload/script` 的 186 组文件。
3. `fnt` 分组的大号字图由 `payload/fnt` 的两张字图覆盖，小号字图取自
   补丁 `en.pak/fnt`，得到配套四图。
4. `IC/uk.pak` 单独保存 `payload/IC/script` 的 30 组脚本。相同场景名的
   主目录与 IC 文件不能合并成一个条目。

原始 PAK 保持外置并继续按需读取。准备工具不运行安装器，不改游戏 EXE、
原有英文包、存档或配置；对已存在的输出应拒绝覆盖。输入需先验证发布散列、
清单、ZIP 路径、KCAP 边界、脚本配对和字体格式，再原子发布输出。

原包中无需改变的压缩成员直接复制其压缩数据；新增大字图可使用游戏原有的
无损压缩格式。不得用 ZIP 数据冒充 KCAP 成员。准备工作只针对这份补丁，
不批量解压原版游戏的大资源包，也不把 PAK 或字图装进 APK。

这一方案比在 Android 上逐个打开数百份散文件更容易保持现有的索引、缓存
和资源读取性能，也避免新增一套仅供某个平台使用的游戏加载实现。具体耗时、
输出体积与快进性能要在实现后测量，不能据此承诺提升倍数。

## 共用代码的修改范围

1. **语言配置与启动页。** 新增 `GameLanguage::ukrainian`、`uk-UA` 和
   `Українська`。脚本与字体都从同一份混合 `uk.pak` 的对应分组读取；
   启动页明确显示路径。Windows 使用同一配置。启动配置拟升级至 v8，
   保留 v7 及更早配置已有语言与开关，中文仍为默认。
2. **资源适配器。** 将混合语言包的分组解析复用于乌克兰配置。主目录脚本、
   IC 脚本、共用字体与界面分别解析；缺失项按 PC 补丁相应的后备顺序处理。
   保留既有 `patch.pak` 优先级，并在诊断中标出实际资源来源，便于定位
   与其他语言补丁的冲突。
3. **姓名与文字处理。** 用经校验的元数据初始化姓名；将上述两处引号规则
   与字符推进规则加入共用 C++/静态生成流程，仅在乌克兰配置启用。
   继续保持代码页不可写，不加载或执行作者的 EXE/DLL，不引入运行时译码器。
4. **内置提示。** 为存读档等七处提示准备与字库匹配的语言文本，检查
   原容量与布局。须先确定补丁完整的字符编码关系；直接沿用当前英文提示
   可能被乌克兰字图显示成错误字符，不能只增加下拉选项便宣称完成。
5. **字幕。** 普通对白随乌克兰脚本显示；现有补充字幕开关独立保留。
   若要接入 `todokanai/subtitles`，需先核对四个头字段的 PC 触发语义，
   再映射到 `soundEffect`/`voice` 与 `begin/end`，经过现有严格解析器校验。
   当前包中的英文字幕不能标为乌克兰语翻译。

所有游戏行为只实现于共用源码。Android 与 Windows 的差别仍只限于 OS、
窗口、输入、设备音频、文件访问和显示适配。

## 验收顺序

1. 在自有内存/临时文件中验证准备工具的拒绝覆盖、损坏输入处理、逐成员
   字节一致性、主目录/IC 冲突隔离和四图选择；不发布游戏资源。
2. 对两处引号与字符推进规则做同分支的有限输入比较，覆盖普通字符、
   四种修正字符、标签、不同尺寸、换行和姓名；确认其他三种语言不变。
3. 检查 32 个姓名槽、七处提示、旧启动配置迁移，以及源代码页和字形表
   未被运行时修改。新存档与载入存档后的姓名/文本状态也要分别检查。
4. 单任务、隐藏、低优先级构建 Windows x64 与 Android ARM64，核对共用
   静态源集合、APK 版本/签名。新 APK 按项目约束通过 ADB 覆盖安装并校验。
5. 实际画面、剧情、读档和快进由玩家操作实测；组件通过不代表全剧情兼容。
   开发过程中不启动游戏、不操作菜单、不读取屏幕。

本次交付的是已基于实际输入分析的接入方案与检查结论；准备工具、语言选项、
三处文字行为和字幕转换尚未实现，尚无乌克兰语支持 APK。
