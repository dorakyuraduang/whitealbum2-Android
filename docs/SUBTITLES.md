# 内置正篇语音字幕

从 `0.2.39-shared-aot` 起，Windows x64 与 Android ARM64 共用同一套
正篇语音字幕实现。数据来自
[nxs7/WA2-CHS-Subtitle-Patch](https://github.com/nxs7/WA2-CHS-Subtitle-Patch)
固定提交的根目录 `script/sub.yaml`，包含 46 段音频、315 条字幕。
默认生效，不需要把原补丁 DLL、`subtext.dat` 或 `subfont.tga` 放到资源目录。
这是为原游戏中只有声音的片段补充文字，不是重新汉化全部剧情。

整个 `SpecialContents` 字幕集都没有导入、编译或打包。根目录正篇字幕中的
`scene=9500` 是原游戏人物采访的编号，仍按该文件的内容保留；不会加入
Special Contents 的广播剧、附加歌曲等数据。

语音使用音频自身的场景编号与 ID；复用到别的剧情场景时仍能匹配。音效使用
音效 ID。现有静态音频函数完整执行后才发送字幕事件，相同通道停止时清除字幕。
没有增加逐指令钩子，也没有跳过、改写原音频函数。时间采用原补丁的毫秒区间，
延迟提交一帧时直接选取当前区间，避免逐句追赶已经过期的文字。

字幕状态由独立的原生服务持有，运行时与兼容进程的原有类布局不变，继续核对
历史对照库的 ABI。运行时仅首次解析服务绑定，后续音频事件和绘制不查询注册表。

显示使用当前游戏的等比例视口，白字、黑描边、顶部居中，过长的字幕自动换行。
字幕变化或视口调整时才重建几何；使用时上传一份只含 891 个字符的共享字图，
不逐帧读取字幕文件、生成字体或重新上传字图。原游戏 PAK 保持外置。

`0.2.40` 修正后台缓冲区大于实际显示区域时的字幕缩放与位置。例如游戏只显示
1920×1080 后台中的 1280×720 区域时，旧换算会将字幕放大 1.5 倍，并把横向
中心从 640 移到 960，导致右侧文字裁切。现在完整的 1280×720 字幕画布直接
适配最终可见游戏视口，统一缩放、顶部居中；不再经过后台分辨率和源裁切的二次
换算。换行继续按字幕画布计算，不让黑边参与排版。内存回归检查覆盖 16 种后台、
裁切、窗口缩放及手机横竖屏组合，逐字检查全部 315 条字幕的最终位置和大小。

许可和来源见 [third_party/wa2_subtitles](../third_party/wa2_subtitles/README.md)。
内存检查覆盖全部字幕时序、原始音频 ABI、停止/覆盖、字图和布局，着色器使用
桌面 GL 与 GLES3 的离线编译/链接检查。按项目约束没有启动游戏、模拟器或读取
屏幕，手机实际显示、音画同步及完整剧情兼容性仍需实机验证。
